# ADR-0001 · 单位、坐标系与坐标轴约定

- 状态：已采纳（阶段 0）
- 日期：2026-10-19

## 背景

生成器（Blender Python）、导出管线（glTF → UE5）与远期网页版需要共享一套单位与轴向约定，否则会出现「1 m 还是 1 cm」与「Y-up 还是 Z-up」的反复返工。UE5 原生单位为厘米、Z 轴向上；Blender 亦为 Z 向上，但 glTF 导出默认转换为 Y-up（需在导出时显式约定）。

## 决策

1. **场景长度单位 = 1 cm**。所有几何函数输出以厘米为数值单位，`1.0` 即 1 cm，与 UE5 1 uu = 1 cm 直接对齐；导出 glTF 时为避免单位放大，沿用 Blender 场景单位 1.0 = 1 m 的引擎约定需在导出层确认（glTF 规范以米为单位，导出器按 Blender 场景单位换算；本步导出用于预览，不接 UE5）。
2. **Z 轴向上**，右手坐标系。
3. **X 轴 = 面阔方向**（建筑横向），**Y 轴 = 进深方向**（建筑纵深），**建筑正面（前檐）朝 −Y**。建筑平面以柱网几何中心为原点 `(0, 0)`。
4. **营造尺换算**：`1 尺 = 32.0 cm`、`1 寸 = 3.2 cm`，定义在 `blender/generator/units.py`，为可配置常量；清代营造尺学界折算约 31.96–32 cm，取 32.0 作为项目基准。
5. **斗口等第**：一等 6.0 寸 → 十一等 1.0 寸，每等递减 0.5 寸，共 11 等；大式建筑尺寸由斗口（cm）驱动。
6. **命名**：代码标识符用英文，注释与文档保留中文营造术语（檐柱、金柱、攒档、上檐出、举架、山花、撒头等）。

## 后果

- 所有构件模块（platform / columns / beams / brackets / roof）接收厘米参数，返回厘米坐标的网格数据。
- 后续接入 UE5 时只需在导出层做一次单位/轴向映射，不在生成器内部做转换。
- 网页版（Three.js / CesiumJS，米制、Y-up）同样在导出层换算。

## 备注

- 本 ADR 只覆盖单位与轴向；材质、LOD、命名细则留待后续 ADR。
